# Platform Admin local guide

1. Use Node 24. Copy `backend/.env.example` to the ignored `backend/.env` and set an exact `MONGODB_URI` and `AUTH_TRUSTED_ORIGINS=http://localhost:3000`. Set `ADMIN_BOOTSTRAP_DATABASE` to the database path in `MONGODB_URI` (for example `savora_dev`). The command refuses `dbName` overrides, noninteractive use, a mismatched database, and a second Admin. For `savora_dev` it requires `savora_dev_user`; for `savora_test`, `savora_test_user`.
2. From `backend/`, run the bootstrap **manually** in an interactive terminal. On this machine, the exact Node 24 command is `& 'C:\Users\EL-B\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' --env-file=.env src/cli/bootstrap-platform-admin.js`. Check the executable's `process.version` and `process.execPath` first; the default `node` here is Node 20, so `npm run admin:bootstrap` is suitable only after the operator has selected Node 24. Enter the Admin email, hidden password twice, and type the exact database name at the confirmation prompt. This is an explicit database write; it is never part of startup or tests against `savora_dev`.
3. Start `npm run dev` in `backend/` and `frontend/` using Node 24. Set `NEXT_PUBLIC_SAVORA_API_BASE_URL=http://localhost:5000` in ignored `frontend/.env.local`.
4. Open `/en/admin/login` or `/ar/admin/login`. Sign in with the bootstrapped account. Owner credentials use `/dashboard/login` and cannot open Admin APIs.
5. Use **Restaurants → Add restaurant** to enter the tenant name/slug/currency and initial Owner name/email/password. The password is sent only in the protected creation request and is not displayed again. Hand it to the Owner through an operator-approved secure channel. There is no email delivery or reset in this phase.
6. Review the new record in the Restaurants list and detail page. To suspend, open details and explicitly confirm. Public storefront routes become unavailable, checkout is rejected, and Owner access ends. Reactivation is available from the same detail page. Each transition is audited.
7. Log out when finished. A revoked session cannot be restored. Avoid saving Admin or initial Owner passwords in browser password sharing, tickets, screenshots, or logs.

The existing `provision:dev` Owner provisioning CLI remains as a guarded fallback. It does not create a Platform Admin. Production use requires deployment-specific index inspection/rollout, shared rate limiting, trusted HTTPS origins, and an approved bootstrap target; this guide does not authorize deployment or development database writes.
