دليل مشروع Food Delivery

شرح عملي لهيكل مشروع Next.js الخاص بطلبات وإدارة مطعم: ما وظيفة كل مجلد وملف، كيف تتحرك البيانات، وما المطلوب عند تركيب الباك إند وتحويله لمنتج قابل للبيع.

اسم المشروعfood-delevery
الإصدار0.1.0
تاريخ الدليل27 يونيو 2026
المشروع يستخدم Next.js 16.2.7. بناء على دليل Next المحلي داخل node_modules/next/dist/docs، ملف src/proxy.ts هو بديل Middleware في Next 16، و route groups مثل (public) و (dashboard) لا تظهر في الرابط.

ملخص المشروع

المشروع عبارة عن واجهة أمامية كاملة لمطعم باسم Bistro Central / Savora: صفحة رئيسية، منيو، سلة، Checkout، تتبع طلب، ولوحة تحكم لإدارة المنتجات والأقسام والطلبات والإعدادات. البيانات حاليا mock داخل src/data، ويتم الوصول لها من src/services.

نقاط القوة الحالية
  • تصميم جاهز ومتماسك للعميل والإدارة.
  • دعم عربي/إنجليزي مع RTL.
  • State للسلة والطلبات باستخدام Zustand.
  • تقسيم جيد حسب features وخدمات وأنواع بيانات.
الحدود الحالية
  • لا يوجد باك إند حقيقي أو قاعدة بيانات.
  • تسجيل دخول الإدارة واجهة فقط.
  • إضافات وتعديلات الداشبورد محلية وتضيع عند refresh.
  • Checkout لا ينشئ طلب حقيقي حتى الآن.

كيف تمشي البيانات؟

  1. الصفحات داخل src/app/[locale] تستقبل اللغة من URL.
  2. الصفحة تستدعي service من src/services مثل getProducts(locale).
  3. الـ service يقرأ من mock data داخل src/data ويطبق تعريب من localized.ts.
  4. الصفحة تمرر البيانات إلى مكونات feature داخل src/components/features.
  5. السلة وحالة الطلب الحالية محفوظة في stores داخل المتصفح باستخدام Zustand.
عند تركيب الباك إند الأفضل ألا تغير كل الصفحات. ابدأ بتعديل src/services لتقرأ من API، ثم أضف auth/session، وبعدها اربط إنشاء الطلب وتحديث الحالات بقاعدة البيانات.

خطة تركيب الباك إند

  • اعمل API للمنتجات والأقسام والطلبات والإعدادات: products, categories, orders, restaurant.
  • استبدل mock functions داخل src/services بطلبات fetch أو client مناسب.
  • أضف auth حقيقي للداشبورد: login، session، role admin/staff، وحماية routes.
  • اجعل Checkout ينشئ order حقيقي ويرجع orderNumber للعميل.
  • اربط DashboardOrdersPage بتحديث status في قاعدة البيانات وليس state محلي.
  • أضف رفع صور للمنتجات بدلا من كتابة image URL فقط.
  • احفظ إعدادات المطعم والتوصيل وساعات العمل في قاعدة البيانات.
  • استخدم env vars لعناوين API ومفاتيح الدفع والتخزين.

رأيي في المشروع

المشروع واجهته قوية كبداية تجارية: الشكل جذاب، التقسيم مفهوم، وتجربة العميل والإدارة موجودة بنسبة كبيرة. بعد تركيب باك إند حقيقي، Auth، قاعدة بيانات، ودفع/إشعارات، يقدر يتحول لمنتج قابل للبيع لمطاعم صغيرة ومتوسطة. أكبر قيمة فيه حاليا أنه ليس مجرد landing page؛ فيه دورة طلب شبه كاملة ولوحة تحكم جاهزة بصريا.

إضافات تجعله أسهل في البيع

  • نظام multi-tenant: كل مطعم له منيو، شعار، ألوان، دومين أو subdomain.
  • دفع إلكتروني: Stripe/Paymob/PayPal حسب السوق، مع cash on delivery.
  • إشعارات WhatsApp/SMS للعميل والمطعم عند إنشاء الطلب وتغيير الحالة.
  • لوحة مطبخ Kitchen Display تعرض الطلبات الجديدة وتسمح بتغيير الحالة بسرعة.
  • كوبونات وخصومات ورسوم توصيل حسب المنطقة.
  • إدارة فروع ومناطق توصيل وساعات عمل لكل فرع.
  • تقارير مبيعات حقيقية: يومي/شهري، أفضل المنتجات، متوسط قيمة الطلب، ومصدر الطلبات.
  • PWA أو تطبيق بسيط للموبايل، خصوصا للإدارة والمطبخ.
  • SEO و Open Graph لكل منتج حتى يظهر المنيو بشكل ممتاز عند المشاركة.
  • اختبارات أساسية و seed data و deployment جاهز، لأن ده يرفع ثقة العميل وقت البيع.
